MODULE 01

Representation

Embeddings & similarity

Every modern model begins by turning things into vectors: lists of numbers positioned in a high-dimensional space of meaning. Similar things land close together. The standard way to measure "close" is cosine similarity: the cosine of the angle between two vectors, running from 1 (identical direction) through 0 (unrelated) to -1 (opposite).

Because words are vectors, you can do arithmetic on meaning. The famous example takes the vector for king, subtracts man, adds woman, and lands near queen.

PYTHON · cosine similarity from scratch Open in Colab
import numpy as np

def cosine(a, b):
    a, b = np.array(a), np.array(b)
    return a @ b / (np.linalg.norm(a) * np.linalg.norm(b))

king  = np.array([2, 3, 9]);  man   = np.array([2, 5, 7])
woman = np.array([3, 5, 6]);  queen = np.array([3, 3, 8])

analogy = king - man + woman          # vector arithmetic on meaning
print(cosine(analogy, queen))          # ~0.99  -> lands near "queen"

Take-aways

  • I can compute cosine similarity and do vector arithmetic on embeddings.
  • I can demonstrate the bias embedded in vectors and judge its downstream impact.
  • I know that computer vision works the same way: a CNN reads an image as grids of pixel numbers.

Evaluation: precision vs recall

Training a model is easy; knowing whether it's any good is the real skill. We compare predictions to the truth in a confusion matrix, then derive precision (of the things flagged, how many were right?) and recall (of the things that mattered, how many did we catch?). A single threshold controls the trade-off.

Raise the threshold → precision climbs but recall falls (you miss real spam). Lower it → you catch more spam but throw false alarms. You pick the metric that matches the stakes.

Concept · overfitting

A model that scores 100% on the data it trained on but poorly on unseen test data has overfit: it memorised instead of learning. That is why we always hold out a test set and report the test score, never the training score.

PYTHON · forward pass + evaluate Open in Colab
import numpy as np

def sigmoid(z): return 1 / (1 + np.exp(-z))

def forward(X, W, b):              # one linear layer + activation
    return sigmoid(X @ W + b)

X = np.array([[0.9,0.7],[0.2,0.1],[0.8,0.9],[0.3,0.4]])
y = np.array([1, 0, 1, 0])           # ripe? (true labels)
W = np.array([1.5, 1.0]);  b = -1.4

pred = (forward(X, W, b) >= 0.5).astype(int)
print(pred, (pred == y).mean())      # predictions and accuracy

One model, three phases: training, fine-tuning & inference

Stack neurons into layers (early layers learning simple features, deeper layers combining them into concepts) and you have deep learning. Every deep model then lives through three phases. Training (called pretraining for large models) is the expensive one: the model sweeps huge amounts of general data while gradient descent adjusts the weights until general patterns stick. Fine-tuning continues training that pretrained model on a smaller, focused dataset (medical notes, legal contracts, polite dialogue) so it specialises without starting from scratch; RLHF is fine-tuning where the "dataset" is human feedback ranking the model's own answers. Inference is game day: the trained model answers your prompt using the weights it already has: no weights change at all.

Checkpoint · training, fine-tuning or inference?

A hospital takes a language model already pretrained on general web text and continues training it on 50,000 anonymised discharge summaries so it writes better clinical notes. Which phase is that?

Pick one: whether the weights update, and on what data, is the tell.

  • I can read a confusion matrix and compute precision, recall and accuracy, and pick the metric that matters.
  • I know the layers of deep learning, and the difference between training, fine-tuning, and inference.
MODULE 03

Generation

The transformer pipeline & sampling

A large language model is a next-token predictor. Text flows through a fixed pipeline: it is split into tokens, each token becomes an embedding, attention lets every position weigh the others, and out come probabilities over the whole vocabulary. Finally we sample from those probabilities, and one dial, temperature, controls how adventurous that sampling is.

Interactive · temperature & sampling

Fixed model scores (logits) for the next token after "The cat sat on the ___". Move the temperature and watch the distribution reshape.

temperature T1.0

Low temperature makes the top token almost certain: safe but repetitive. High temperature flattens the distribution: creative, but more likely to go off the rails. This single trade-off is why the same prompt can give different answers.

Interactive · trace the transformer
PYTHON · softmax with temperature Open in Colab
import numpy as np

def softmax(logits, T=1.0):
    z = np.array(logits) / T
    z = z - z.max()                    # numerical stability
    e = np.exp(z)
    return e / e.sum()

logits = [3.0, 2.0, 1.5, 0.5, -1.0]    # mat, floor, sofa, roof, banana
print(softmax(logits, T=0.5))          # peaked  -> almost always "mat"
print(softmax(logits, T=1.5))          # flatter -> more variety (and risk)
Concept · diffusion

Image generators use a different idea: diffusion. A model learns to take an image buried in random noise and remove that noise step by step, conditioned on your prompt, until a picture emerges, like reversing static back into a photo.

Take-aways

  • I can trace the transformer pipeline end to end: tokens → embeddings → attention → next-token probabilities → sampling.
  • I can compute a softmax with temperature and interpret the usefulness-versus-reliability trade-off.
  • I know diffusion generates images by reversing noise, conditioned on a prompt.
MODULE 04

Interaction

Prompting, agents & RAG

A model is only as good as how you steer it. A system prompt sets its role and rules; few-shot examples show it the pattern to copy; and chain-of-thought ("think step by step") makes it reason before answering. Together they turn a raw model into a reliable tool.

PROMPT · system + few-shot + chain-of-thought 
SYSTEM: You are a careful maths tutor. Always show your steps.

# few-shot example teaches the format
Q: A shirt is $40 with 25% off. Final price?
A: 25% of 40 = 10.  40 - 10 = 30.  Answer: $30.

# chain-of-thought on the real question
Q: A $240 jacket has 15% off. Final price?
A: Let's think step by step. ___

A plain model only talks. An agent can act: it runs a loop (plan, call a tool, observe the result, then re-plan) until the goal is met. Step through one below.

Interactive · an agent's tool-calling loop
Concept · retrieval-augmented generation (RAG)

RAG fetches relevant, trusted passages first, then asks the model to answer using only those sources, and to cite them. It grounds answers in real documents, which cuts hallucination. But it has limits: if retrieval brings back the wrong passage, the model can still be confidently wrong.

PSEUDOCODE · the agent loop 
goal = "What is 15% of $240?"
while not done:
    thought = model.plan(goal, memory)
    if thought.needs_tool:
        obs = call(thought.tool, thought.args)   # calculator -> 36.0
        memory.add(obs)                          # observe, then re-plan
    else:
        answer = model.respond(goal, memory)
        done = True

Take-aways

  • I can construct chain-of-thought, system and few-shot prompts.
  • I can design and evaluate a multi-step agent or RAG system against a defined metric.
  • I know how an agentic system plans, calls tools, observes and re-plans, and where each can fail.
MODULE 05

Responsibility

Fairness, limits & governance

The most important module. A model trained to predict the most plausible next token is not optimising for truth, so a hallucination (a fluent, confident, false answer) is a built-in risk, not a bug. Techniques like RLHF and RAG reduce it but never fully remove it. Using AI responsibly means measuring its harms, not just its accuracy.

Interactive · fairness audit

A loan model is 90% accurate overall. Impressive, until you break the score down by group.

Aggregate accuracy can hide serious harm to a subgroup. Auditing per group, and writing it down in a model card, is how you catch it before it ships.

Artifact · a model card (excerpt)
# Model Card: LoanScorer v0.3
Intended use : screen applications for human review (NOT auto-decide)
Training data: 40k past loans, 2019-2024 (under-represents rural applicants)
Metrics      : accuracy 0.90 | recall(group A) 0.94 | recall(group B) 0.71
Limitations  : weaker on thin credit histories; do not use outside training region
Risks        : disparate impact by group -> require human oversight + appeal route
Concept · governance & real-world cost

Governance means accountability, transparency and explainable AI (being able to say why a decision was made). And every answer has a physical cost: training and running large models consumes real energy and water. Responsible design weighs the benefit against that footprint.

Take-aways

  • I can interpret fairness metrics and error types, and audit a model or dataset, documenting it in a model card.
  • I know why hallucination follows from the next-token objective, and the limits of RLHF and retrieval.
  • I care about governance, accountability, and the societal and environmental cost of what I deploy.
